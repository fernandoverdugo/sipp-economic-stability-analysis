# Longitudinal Panel Construction

Milestone 3 builds the first validated 2024→2025 SIPP person panel from official Census public-use files.

## Inputs

The panel uses:

- 2024 SIPP primary file
- 2025 SIPP primary file
- 2025 two-year longitudinal person-weight file
- 2025 two-year longitudinal replicate-weight file

Raw Census files remain outside Git history.

## Person-year collapse

The SIPP primary file is organized at the person-month level. The project therefore does **not** assume one row per person.

For each release, the panel builder:

1. reads only the required fields from the very wide primary file
2. groups records by `SSUID + PNUM`
3. verifies that annual `TFCYINCPOV` is constant across that person's monthly records
4. verifies that annual `TAGE` is constant across monthly records
5. records the number of observed reference months
6. collapses to one validated person-year record

The implementation uses a streaming parser so the 4,000+ column primary files can be processed without loading the full microdata into memory.

## Longitudinal linkage

The two person-year files are linked using:

```text
SSUID + PNUM
```

The linked persons are then intersected with both:

- the two-year longitudinal weight file
- the two-year longitudinal replicate-weight file

The resulting panel contains only persons represented in all required analytical components.

## Weight validation

The primary longitudinal analysis uses `FINYR2`.

The replicate-weight file also contains `REPWGT0`, which represents the corresponding full longitudinal weight.

The maximum observed absolute difference was:

```text
0.000010000003385357559
```

This is below the project's documented serialization tolerance of `0.0001`.

The tolerance exists only to accommodate decimal serialization differences between the two Census files; it is not a substantive weighting adjustment.

## Analytical cohort

The flagship analysis is restricted to adults age 18 or older at baseline.

Additional requirements:

- valid baseline annual family poverty ratio
- valid follow-up annual family poverty ratio
- positive `FINYR2`

Final adult analytical cohort:

```text
15,034 persons
```

## Poverty transitions

Poverty is provisionally defined as:

```text
TFCYINCPOV < 1.0
```

The four transition states are:

| Transition | Unweighted n | Weighted share |
| --- | ---: | ---: |
| Stable above poverty | 12,877 | 86.28% |
| Entered poverty | 587 | 3.65% |
| Exited poverty | 757 | 4.88% |
| Persistent poverty | 813 | 5.20% |

Derived weighted point estimates:

- baseline poverty prevalence: **10.07%**
- follow-up poverty prevalence: **8.84%**
- poverty entry among adults above poverty at baseline: **4.05%**
- poverty exit among adults below poverty at baseline: **48.43%**

These values are **point estimates only**. Confidence intervals and standard errors will not be reported until Milestone 4 applies the Census longitudinal replicate weights.

## Reproducibility

The full panel profile is generated by:

```bash
python src/download_assets.py --mode all
python src/build_panel.py
```

The aggregate profile is committed at:

```text
data/metadata/panel_profile.json
```

The person-level panel is written to:

```text
data/processed/panel_core.csv.gz
```

and remains excluded from Git history.

## Engineering lessons

Building the panel exposed several real Census-file integration issues:

- primary and longitudinal files do not use identical header capitalization
- the large primary files require streaming rather than wide in-memory parsing in CI
- shell piping can mask Python failures unless `pipefail` is enabled
- `FINYR2` and `REPWGT0` differ by tiny decimal serialization amounts

These conditions are now explicitly tested or handled in the reproducible pipeline.
